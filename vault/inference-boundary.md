# Inference boundary

Teach this cut. A chat is the window. A harness is the machine around the window. Token Maxxing keeps that window for the job.

The model infers. The harness executes. Same arguments, same result, and no model inside, is the harness side. A choice made from text is the model side.

The tool call crosses. The server stays. Call the server deterministic when it does not call a model and the arguments are a handle, an enum, or a path. A thick result is a thick gate. It does not change what the server is.

## Three crossings

A hook does not cross. The 80% fire and the completion flag run because a rule fired. The model did not decide.

A thin call crosses once. The name is already in the tool list. The model sends a handle. The server already has the store. The result is short.

A skill crosses and stays. The catalog is a name and one line. Opening a skill copies the chapter into the window. That chapter is sent again on later calls. A skill is natural language the model follows. It does not run.

## Where this vault sits

This vault is notes plus the scripts in `scripts/`. It is not in the tool list. Reading a note, or loading a skill that points at a note, is the skill path. The chapter enters the window.

Firing a script is a shell command. The script is deterministic. Reaching it is not, because the model has to find the path and compose the line. That is why the toolbox can feel like a skill repository and like a fast tool at the same time. It is the first until a successful script is placed in the tool list with a handle for an argument.

[[deliver]] is not the hop-80 close. [[inject-harness]] types one line. The packet file is the first message. [[hop-80]] closes the tail only after that inject exits 0. [[open-harness]] is the same start, with no 80% gate and no tail close.
